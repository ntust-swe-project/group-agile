### yichieh-chen（EJ）
**Keep**
1. 看板、認領、hook 那套大家都有照著走，沒什麼亂掉的狀況
2. PR 大部分開出當天或隔天就 merge，回得很快
3. 提案 → story 的流程有用，S07～S09 都是這樣來的

**Improve**
1. review 比較像「換另一個人叫 AI 再看一次」，很少真的看懂彼此的 code（負責人：全員）
2. 有依賴的 story 要等前面 PR merge，story PR 全擠在 11/11；PR 也偏大，像 S05（#42）改了 27 個檔，卡了快一週（負責人：PO 拆 story 時注意大小、作者控制 PR 大小）

**Try**
1. 開 PR 前作者先跑 `/code-review` 修完；reviewer 改做 AI 做不到的事：實際開遊戲照驗收條件玩一下，用自己的話講這個 PR 在做什麼
2. 測試全過就先 merge、review 之後補；有改到共用檔案（`events.gd`、`main.tscn`、config）就再自己玩一場，並通知會被影響的人。權限、hook、CI 等流程設定維持先 review（要先確認課程有沒有規定 merge 前一定要 review）
3. 有依賴的 story 先開小 PR 把 signal／資料格式定好先合，大家就能同時做；每人每天把 main 合進自己的 branch 一次，PR 控制在半天做得完的量
